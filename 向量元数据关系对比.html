Analysis · Vector & Metadata Binding

向量与元数据关系对比

对比 RAG问答(LangChain).py（Native RAG）与 迪士尼RAG查询.py / 迪士尼RAG知识库.py（多模态） 中，向量索引与元数据如何协同、如何用编号取回可读内容。

一句话结论

两边都是「向量找近邻 → 用编号取元数据」。 Native 用 IndexIDMap 显式 ID 绑定； 迪士尼用 插入顺序下标 隐式绑定。

构建阶段：如何写入

Native RAG

IndexIDMap + add_with_ids

显式把列表下标写成 FAISS ID，向量与元数据用同一套 ID 对齐。

flowchart TD
  A[PDF 切分 chunks] --> B[metadata_store
id / page / text]
  B --> C[text-embedding-v4
生成向量]
  C --> D[IndexFlatL2]
  D --> E[IndexIDMap 包装]
  B --> F["ids = 0..n-1"]
  C --> G[add_with_ids
vectors, ids]
  E --> G
  F --> G
  G --> H[(index.faiss)]
  B --> I[(metadata.pkl)]
  C --> J[(vectors.npy)]
迪士尼多模态

IndexFlatL2 + add

按写入顺序自动编号 0,1,2…；第 i 个向量对应 metadata[i]。

flowchart TD
  A[文档 / 图片 / 视频] --> B[各自 Embedding]
  B --> C[all_vectors.append]
  A --> D[metadata_store.append
type / content / path / url]
  C --> E[IndexFlatL2]
  E --> F["index.add 向量
行号 = 插入顺序"]
  D --> G[(disney_metadata.json)]
  F --> H[(disney_index.faiss)]
  C -. 顺序必须一致 .-> D

查询阶段：如何取回

Native RAG

search → FAISS ID → 元数据

flowchart LR
  Q[用户问题] --> E[embed_query]
  E --> S["index.search → distances, ids"]
  S --> M["metadata_store[faiss_id]"]
  M --> R[拼 context + 页码]
  R --> L[LLM 回答]
迪士尼多模态

search → 行号 idx → 元数据

flowchart LR
  Q[用户问题] --> E[文本 Embedding]
  E --> S["index.search → distances, indices"]
  S --> M["metadata[idx]"]
  M --> T{按 type 筛选}
  T -->|text| C[Top-k 文本进 Prompt]
  T -->|image/video| V[阈值内取媒体]
  C --> L[LLM 回答]
  V --> L

差异总览流程图

同一目标、两种钥匙：显式 ID vs 位置下标。

flowchart TB
  subgraph common [共同目标]
    G1[向量近邻检索] --> G2[用编号取元数据] --> G3[拼上下文 / 返回答案]
  end

  subgraph native [Native: 显式 ID]
    N1[IndexIDMap] --> N2[add_with_ids]
    N2 --> N3[检索返回自定义 ID]
    N3 --> N4["metadata_store[id]"]
  end

  subgraph disney [迪士尼: 隐式顺序]
    D1[IndexFlatL2] --> D2[add 按序写入]
    D2 --> D3[检索返回行号 idx]
    D3 --> D4["metadata[idx]"]
  end

  common --> native
  common --> disney

  N4 --> OUT1[稳定：删改后仍可按 ID 对齐]
  D4 --> OUT2[简单：必须保证向量与元数据顺序同步]

对照表

维度 Native RAG（LangChain） 迪士尼多模态
索引类型 IndexFlatL2 + IndexIDMap 纯 IndexFlatL2
写入方式 add_with_ids(vectors, ids) index.add(vectors)
检索返回 自定义 FAISS ID 向量行号 idx
取元数据 metadata_store[faiss_id] metadata[idx]
元数据字段 id / page / text type / content / path / url 等
落盘文件 index.faiss + metadata.pkl + vectors.npy disney_index.faiss + disney_metadata.json
增删改鲁棒性 较高：ID 层可独立于物理行号 依赖顺序：列表与索引必须同步重建
当前为何两边写法看起来很像？ Native 把 id 也设成了 0..n-1，所以也能写成 metadata[编号]。 一旦以后删除或重排条目，Native 仍可按 ID 对齐；迪士尼则必须保证向量顺序与元数据列表永远一致。
